对外文案（README、Release 说明、GitHub 简介、官网）一律书面语，措辞正式、凝练。主人说的是想法和方向，写进文档要提炼、重组、打磨，不照着原话抄。

**Why:** 2026-11-13 改 README 时被连续纠正：「太口语化了」「我只是跟你交流我的想法而已，并不是让你照着我的原话去抄」。致谢 UU远程 那段改了三版：照抄太单薄 → 加强了但口语 → 书面语才过。

**How to apply:**
- 先把主人的话拆成要点，每个要点讲出分量（比如高质量为什么是门槛），再用书面语重写；口语词换掉（「跟手」→「响应灵敏」）
- 能分点就分点，少大段文字；少量 emoji 只放标题；README 是门面，技术细节放 docs/
- 图文对应：图放在它说明的那一步旁边；单独的图前面先用一句话点题
- 截图、录屏打码只糊必要的一小块（个人信息、文件链接），不整片糊（主人：「全都糊成一片看啥」）；主人说不介意的内容就不打

- **简洁干练，不写口语化的主谓宾陈述句**（11-18 讨论 README 重组时）：我给的中文标语候选（「无论用什么设备远程 Mac，都像原生一样顺手」之类）和目录说明被评「太口语化」。对外文案用短语式、名词化的书面表达（如「按电脑分辨率建屏 · 铺满无黑边」），少用「你」「就」「都能」串起来的完整句子；和主人讨论文案方案时，示例本身也要按这个标准写
- **同一天又被纠正一次，要当硬标准**（11-18 晚加「自定义屏幕」时）：主人评整份 README 和我的草案「太幼稚」「要么全是主谓宾，要么就是谓宾，口语化而且很长」，要「简短干练、官方语言」，并让把全文有问题的一起改掉。改法（2.6.2 之后那版 README 是样板）：
  - 条目写成名词短语或「动词 + 宾语」的短语，不写带主语的整句：「将这块屏设为主屏后，连接即进入这块屏」→「设为主屏后，连接直接进入此屏」；「默认选中整张」→「默认全选」
  - 去掉虚字：「的」「了」「会」「就」「都」「也」「再点一次」，换成「均」「亦」「即」「再次轻点」；「挪」「放到」「关掉」「见」→「移至」「关闭」「参见」
  - 句首的「于」别滥用（「于设置中关闭」读着像文言），句首用「在」；「显示于」「运行于」「适用于」这类动词带「于」的照用
  - 一个条目只说一件事，长句拆成分号短句
